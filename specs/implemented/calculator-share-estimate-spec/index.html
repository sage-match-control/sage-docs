    0. How to use this spec¶

    You can carry this out with no other context: every value, every edit, every test and every check is here. Read §0 to §4 before you change anything.

    0.1 Where things are¶

    The workspace is D:\Personal\SAGE. It holds several independent git repos; two change here:

    Repo Path What changes
    The site D:\Personal\SAGE\sage-match-control.github.io tools/tournament-calculator.html (§5) and one new test file, _tests/unit/tools/tournament-calculator-share.test.mjs (§6)
    The docs D:\Personal\SAGE\sage-docs three docs pages, this spec's status, the changelog and mkdocs.yml (§8)

    The calculator is one self-contained static page: inline <style>, one classic inline <script> (not a module), SheetJS from cdnjs for .xlsx, no build step, no framework. The site's _tests/ folder is the only Node package (dev-only, never published). Nothing in sage-tools-api or event-data changes.

    0.2 Rules¶

    • First, check the team format isn't built. Run grep -c "isTeamFormat" tools/tournament-calculator.html in the site repo. It must print 0.     • Find edits by their anchor text, not line numbers. Every edit in §5 quotes an exact piece of text that occurs once in the file. If an anchor isn't there, or is there more than once, stop and report. Don't guess.
    • Apply §5's edits in order, exactly as written. The code was dry-run (status block). Don't restyle, rename or "improve" it, and don't make design decisions: if this spec seems wrong or two parts disagree, stop and ask the owner.
    • Keep the file's style and line endings. The page is written compactly: 2-space indent, single quotes, semicolons, short names. The working copy has CRLF line endings (git stores LF); keep them. Check with git ls-files --eol tools/tournament-calculator.html: it should still read i/lf w/crlf afterwards, and git diff should show only your lines.
    • Don't touch the maths (calcCategory, calcDualCategory, playoffPlan, seqParts, catTime, calcAll), buildChart, the CSV format (buildPlanCsv, importCSVText), the .xlsx export, GENERATOR_MASTERS, or tools/sw.js. No new dependency anywhere.

    • Commit, but never push or merge without the owner's go-ahead. The site deploys to GitHub Pages on push to main, and takes no merge within 3 days of an event (check the dates in event-data/config/events.json). End each commit message with the attribution line the session gives you.

    1. What the page does¶

    • The Share the estimate box sits in the results column, between the Per-category breakdown panel and the Reset / Import CSV / Export CSV / Download .xlsx buttons. It has a title, one line of help, and two buttons side by side: Save image (green, primary) and Copy text. The file buttons are for the operator's own work; this box is for sending the estimate to someone else, so it sits apart from them.
    • Both buttons are disabled while the plan has no matches (no categories, or a dual-meet category with no pairs), and the help line then reads Add a category first. Otherwise it reads Send the projected finish and the category breakdown to an organiser.
    • Save image draws the estimate (§3) and:
    • on a phone or tablet (a device whose main pointer is coarse, a finger), opens the system share sheet with the PNG attached, so it goes straight to a chat app or Photos. If the share sheet can't take a file, or fails, the PNG downloads instead; if the operator cancels the sheet, nothing happens;
    • anywhere else, downloads the PNG as <file base>-estimate.png, where the file base is the one the .xlsx already uses (fileBase): the title in lower case with every run of non-word characters turned into -, then - and the date. Paddle Aces Day 1's is paddle-aces-the-ultimate-generation-cup-day-1-2026-11-28-estimate.png. It confirms in the page's existing message strip (under the file buttons): Saved <name> or Shared <name>.
    • Copy text copies the message of §4 and confirms Estimate copied — paste it into any chat. If the clipboard is refused it tries the page's existing execCommand fallback (copyFallback), and if that fails too it says Could not reach the clipboard. Use Save image instead.
    • Printing hides the box, as it already hides the file buttons.
    • The finish alert under the big clock reads its level (good, after 10 PM, past midnight) from the same finishLevel the summary uses, so the image's verdict and the page's alert can't disagree. Its wording doesn't change.
    • The category menu gains five presets (§2). Nothing else on the page changes.

    2. The presets¶

    The menu lists, in this order, by level from lowest to highest, Women's, Men's then Mixed in each:

    Level Codes
    Beginner (new) BWD Beginner Women's Doubles · BMD Beginner Men's Doubles · BXD Beginner Mixed Doubles
    Novice NWD · NMD · NXD
    Low Intermediate LIWD · LIMD · LIXD
    Intermediate IWD · IMD · IXD
    High Intermediate HIWD · HIMD · HIXD
    Advanced AWD · AMD · AXD
    Open OWD Open Women's Doubles (new) · OPEN Open Men's Doubles · OXD Open Mixed Doubles (new)
    CUSTOM Custom…
    • Open Men's Doubles keeps the code OPEN. Saved plans, exported CSVs and generated workbooks already carry it; renaming it to OMD would turn every one of them into a custom category on import.
    • A new category still starts from Novice. + Add category picks the first preset not yet used, counting from NWD and wrapping round to BWD after OXD, so a fresh plan starts with NWD as it does today and Beginner is chosen from the menu.
    • Import CSV recognises the new codes. A plan exported with OWD as a custom category (Paddle Aces Day 2's) now imports as the OWD preset, with the preset's name. A plan saved in the browser keeps its custom category until the operator picks the preset.
    • Outside the calculator nothing reads the menu. The Standard Tournament Generator takes any code from the plan CSV. The Dual Meet Sheet Generator colours a category tab by its level and gives none to a level it doesn't know (categoryColor_, as it already does for OPEN and custom codes), so a Beginner or Open category in a dual meet gets no tab colour.

    3. The image¶

    A portrait PNG, 1080 px wide, drawn at 2× (2160 px), as tall as its categories need (Paddle Aces Day 1, ten categories: 2160 × 4900 px, about 1.1 MB). It is drawn on a <canvas> in the page with the page's own colours and fonts (Archivo Black, Barlow Condensed, Inter), with no library. Top to bottom:

    1. Header band (navy): the S.A.G.E. logo (/assets/logo.png, already precached by the service worker) on a white rounded tile, the kicker S.A.G.E. · SCHEDULE ESTIMATE in green, the title in upper case (wrapped), the clubs (PNF vs BUP, dual meet only) in green, then the date and settings line (§4.2's date · meta), with a dashed green rule at its foot.
    2. Projected finish (deep navy box): the label, the finish time large, and the verdict in a pill coloured by its level: green Comfortable one-day plan, amber Finishes after 10 PM, red Runs past midnight.
    3. Four figures in white tiles: pairs, matches (labelled MATCHES, MAX when any category's count is a range), time slots, play time.
    4. Categories (white card, navy title strip): a column head (CATEGORY · FORMAT, MATCHES, TIME), then one row per category with matches: the code in green and the name, the format line and the playoff line in grey (each wrapped); on the right the match count with its RR + PO split under it, and the category's time.
    5. The footnote, then a rule and the signature line S.A.G.E. MATCH CONTROL EXPERTS · TOURNAMENT TIME CALCULATOR.

    The layout runs twice: once to measure the height, once to paint. The band, the table's card and the page background are filled last, behind what is drawn, once their heights are known.

    Why the click draws synchronously. Safari refuses navigator.share unless it starts inside the click. So the fonts and the logo are loaded when the page boots (preloadShareAssets), and the click draws the canvas and encodes it with toDataURL (not the asynchronous toBlob) before calling navigator.share, with no await between. If a font hasn't loaded (offline on a first visit), the canvas uses the fallback faces in each font stack; if the logo hasn't, the tile is drawn empty.

    4.2 The summary¶

    buildEstimateSummary(cfg, r) takes the page's readForm() and calcAll() results and returns one plain object; buildEstimateText and layoutEstimate read only that object. It reads the DOM never, and the page's cats variable never (it reads cfg.cats), which is what lets §6 test it outside a browser.

    Field What it holds
    title The tournament's title, or Untitled tournament
    clubs <Club A> vs <Club B> for a dual meet, else empty
    date The date in full (Saturday, November 28, 2026), or empty when the plan has none
    meta Start 10:00 AM · 10 courts · 25-min matches, with + 5-min buffer when there is one, and 1 court for one
    finish, level, verdict The finish time; finishLevel's good, warn or bad; and its words (§3)
    pairs Every category's pairs, both clubs' for a dual meet (the .xlsx TOTAL row's count)

// plain-text message (buildEstimateText) and a PNG (drawEstimate). Both read

const SHARE_ROUND={'Quarterfinals':'QF','Semifinals':'SF','Bronze match':'Bronze','Final':'Final'};

// The finish alert's three levels; recalc's alert and the summary both read it.
function finishLevel(cfg,r){
  if(!r.matches) return null;

function buildEstimateSummary(cfg,r){
  const dual=cfg.format==='dual';

    const mins=(ct.rr||0)+(ct.po||0)+(ct.rr&&ct.po?cfg.buf:0);
    const k={code:catCode(c),name:catName(c),format:'',playoff:'',count:rng(p.totalMin,p.total),split:'',time:mins?fmtDur(mins):'—'};
    const rounds=()=>p.plan.rounds.map(rd=>SHARE_ROUND[rd.label]||rd.label.replace(/^Round of (\d+)$/,'R$1')).join(', ');

      k.format=p.po?`${p.a} v ${p.b} pairs · ${br} · cross-club group stage`:`${p.a} v ${p.b} pairs · one match decides it`;

  }).filter(Boolean);

    # Question Answer
    D1 Where do the buttons go? A box of their own between the breakdown and the file buttons, since they are for someone else, not the operator's files
