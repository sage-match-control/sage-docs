    0.2 Rules¶

    • Find edits by their anchor text, never by line number. Every anchor is a single line and occurs exactly once in its file. If it isn't there, or is there more than once, stop and report. Don't guess and don't improvise a different edit.
    • Keep each file's line endings. On disk in the site checkout: lib/v1/apps/schedule-board.js, lib/v1/css/schedule-board.css, the three templates' schedule.html, _templates/attendance/attendance.html, _templates/CLAUDE.md and _tests/unit/house-colours.test.mjs are CRLF; _templates/standard-tournament-template/index.html and _templates/dry-run-checklist-template.md are LF, so their copies start as LF. New files you create may be LF; Git stores LF either way. Where an edit replaces several lines, it names the first and the last line of the range and how many lines it spans. Never use sed -i: on this machine it strips the CR from every line. The scripted edits are Node scripts that keep each file's own line ending.
    • Replacement text is given in full in each fenced block. Copy it exactly, including leading spaces. Never retype a value from memory.
    • Use Git Bash for every command. Python is not installed; Node is.
    • Edit only what the phase names. Phase 1: the engine and template files §4 lists, its two new test files, _templates/CLAUDE.md and the docs. Phases 2–4: files in events/generation-cup-2026/, the list in _tests/unit/house-colours.test.mjs, and config/events.json in event-data. Don't edit tools/, _fixtures/ (except by running Appendix A, which you then undo) or any other event's folder. If something there seems to need a change, stop and report.
    • One branch, one commit per phase, in order. Every site change is on the branch gencup, cut in §4.1; each phase is one commit on it, and a phase starts only once the one before it is committed and its checks have passed. In event-data and sage-docs, whose main is worked directly, each phase's commit goes on main and stays unpushed until §7.6.
    • Commit where a phase says Commit, with the message it gives, followed by a blank line and the attribution line your session's instructions give.
    • Never push, and never merge into main, without the owner's yes in chat. Nothing is merged or pushed until §7.6, the one Stop and ask step.
    • Never commit assets/pubmat.jpg. It is reference only.
    • Don't rename, "fix" or tidy anything this spec doesn't mention.

"Ultimate" is --green on --navy, 5.3:1. 3. The font. Anton (Google Fonts) is the closest match to the pubmat's heavy condensed capitals. It is used only for the Hub's title and "2026", and the board's title. 4. The board's colours are the workbooks' where they have them. The generator fills each category's round-robin cells by level and event (Men's blue, Women's magenta, Mixed orange, lighter for a lower level); read off both SCHEDULE tabs through the Sheets API: NMD #C9DAF8, NWD #EAD1DC, NXD #FCE5CD, LIMD #6D9EEB, IWD #C27BA0, LIXD #F6B26B, HIMD #1155CC, HIXD #B45F06. The workbooks leave AMD, AXD and OWD grey (#CCCCCC), so those take the generator's own Advanced shades (#1C4587, #783F04) and OWD its darkest magenta (#4C1130): Open sits above Advanced. The same code has the same colour on both days.

    Since built, Novice and Low Intermediate are one shade deeper (owner's request, 23 November): the board tints a cell 40% over white, and the workbooks' pale shades gave the Novice cells almost the page's own colour (1.00–1.06:1) and a stripe that barely showed. They take the next shade of the same Sheets palette: NMD #6D9EEB, NWD #C27BA0, NXD #F2A55A, LIMD #3470D2, IWD #A64D79, LIXD #E38326; the rest are unchanged. The hue still says the event and the shade the level, and every chip's text reads at 4.5:1 or better. §5.4's block is the colours as first built. 5. The board's Day picker (Phase 1). The board shows one day, its page's DAY_KEY. A page whose markup has the new container <div class="dayfilter" id="dayfilter" hidden></div> reads the event's days from events.json and, with two or more, shows a Day select in the bar, beside the venue and court filters. The board opens on ?day= when it names one of the event's days, else on the day whose date is today, else on DAY_KEY. So Control Center's Open schedule, which opens the board without ?day=, shows Day 1 on 28 November and Day 2 on 29 November with nobody touching it, and Day 1 on any other date. Choosing a day reloads the board with ?day= and drops ?courts= and ?venue=, since Day 1 has 10 courts and Day 2 has 6. The rule is lib/v1/domain/board-day.js, a new pure module with its own tests. A board without the container (every existing one) reads no more than before and is unchanged; the compact header hides the picker, as it hides the court filter. Control Center itself is not changed. 6. The labels (owner's choice, §10): divisions Novice, Low Intermediate, Intermediate, High Intermediate, Advanced, Open; the engine shows <division> <event>, e.g. "Low Intermediate Men's Doubles".     // Which day a schedule board shows, when its page offers a day picker and its event has more than one day
// (sage-docs/docs/specs/.../ultimate-generation-cup-2026-spec.md §4). In order:
//
//   1. the page's ?day=, when it is one of the event's day keys (the picker writes it);
//   2. the event's day whose date is today, so a wall display left on overnight shows the next day's board;
//   3. the page's own DAY_KEY.
//
// With no days read (events.json failed to load), always the page's own DAY_KEY.

/**
 * @param {{ days: { key: string, date?: string }[], dayKey: string, requested?: string|null, today: string }} args
 *   days       the event's days, from events.json (registry.js's eventConfigFrom)
 *   dayKey     the page's own DAY_KEY
 *   requested  the page's ?day=, or null
 *   today      the local date, YYYY-MM-DD (localIsoDate)
 * @returns {string} a day key
 */
export function boardDay({ days, dayKey, requested = null, today }){
  if(!Array.isArray(days) || days.length === 0) return dayKey;
  if(requested && days.some(d => d.key === requested)) return requested;
  const dated = days.find(d => d.date && d.date === today);
  return dated ? dated.key : dayKey;
}

/**
 * A date's local calendar day as YYYY-MM-DD, the form events.json writes a day's `date` in.
 * @param {Date} date
 * @returns {string}
 */
export function localIsoDate(date){
  const pad = n => String(n).padStart(2, '0');
  return `${date.getFullYear()}-${pad(date.getMonth() + 1)}-${pad(date.getDate())}`;
}

    11. Decisions, for reference¶

    • Event key generation-cup-2026, day keys generation-cup-day1 and -day2: short, and the day keys can't collide with any other event's.
    • A Day picker instead of an evening push: the owner's choice. It works for every future multi-day event made from a template, and nothing is pushed inside the freeze.
    • The picker is markup-driven, not a new setting: only a page with the container gets it, so every existing board, including archived ones, is unchanged and reads no more than before.
    • Today's date picks the day when the address doesn't, so the wall display needs nobody on the morning of Day 2. Control Center's Open schedule is therefore not changed.
    • Choosing a day reloads the page rather than swapping data in place: the live channel and the staff view follow the new day with no extra code, and ?courts= can't point past Day 2's six courts.
    • One branch, one commit per phase, one push (the owner's choice, 23 November): each phase is still checked on its own, but npm run verify runs once on the whole branch and everything goes live together, before the 24 November freeze. The events.json entry is written in Phase 2 beside the board it serves, and pushed after the site so Control Center never lists the event before its pages exist.
    • The generation is in the day label, not the division: the workbooks' categories are the same levels on both days, and the label is what every picker shows.
    • The board takes the workbooks' colours for the eight categories that have them, so the wall and the printed schedule agree; only the three grey ones are ours.

function buildDay({ day, label, slots, cats, seed }) {
  // Fixed pseudo-random scores: the same file every run.
  const rand = n => { seed = (seed * 1103515245 + 12345) % 2147483648; return Math.floor(seed / 65536) % n; };
  const score = () => { const loser = rand(10); return rand(2) ? [11, loser] : [loser, 11]; };

  const names = {}, bracketOf = {};
  for (const [cat, [stem, sizes]] of Object.entries(cats)) {
    let n = 0;
    sizes.forEach((size, b) => { for (let i = 0; i < size; i++) { n++; names[`${cat}_${n}`] = [`${stem} ${n}A `, `${stem} ${n}B `]; bracketOf[`${cat}_${n}`] = b + 1; } });
  }
  const rec = {};
  for (const code of Object.keys(names)) rec[code] = { w: 0, l: 0, pf: 0, pa: 0 };
  const tally = (code, pf, pa) => { const r = rec[code]; r.pf += pf; r.pa += pa; if (pf > pa) r.w++; else r.l++; };
  const better = (x, y) => rec[y].w - rec[x].w || rec[y].pf / rec[y].pa - rec[x].pf / rec[x].pa;
  const bracket = (cat, b) => Object.keys(names).filter(k => catOf(k) === cat && bracketOf[k] === b).sort(better);
  const runnersUp = cat => cats[cat][1].map((_, b) => bracket(cat, b + 1)[1]).sort(better);
  const ladder = cat => LADDERS[cats[cat][2]];

  const results = {};   // "<CAT> <match>" -> { winner, loser }
  const seatNames = code => {
    const cat = catOf(code), slot = code.slice(cat.length + 1);
    const row = ladder(cat).find(r => r[0] === slot);
    if (cats[cat][2] === 'final') {
      const order = bracket(cat, 1), i = { F_1: 0, F_2: 1, B_1: 2 }[slot];
      return i === undefined || !order[i] ? BYE : names[order[i]];
    }
    const [, , from, seat] = row;
    if (from) { const r = results[`${cat} ${from.slice(2)}`]; return from[0] === 'W' ? r.winner : r.loser; }
    const m = /^Bracket (\d+) · #(\d+)$/.exec(seat);
    if (m) return names[bracket(cat, +m[1])[+m[2] - 1]];
    return names[runnersUp(cat)[{ 'Best runner-up': 0, '2nd-best runner-up': 1, '3rd-best runner-up': 2 }[seat]]];
  };

  const rows = [], playoffRows = {};
  let num = 0;
  for (const [time, courts] of slots) {
    for (const entry of courts.split(' ')) {
      const [court, c1, c2] = entry.split(':');
      const playoff = !isRoundRobin(c1);
      const p1 = playoff ? seatNames(c1) : names[c1], p2 = playoff ? seatNames(c2) : names[c2];
      const [s1, s2] = score();
      rows.push([++num, '', time, `Court ${court}`, c1, p1[0], p1[1], s1, c2, p2[0], p2[1], s2]);
      if (!playoff) { tally(c1, s1, s2); tally(c2, s2, s1); continue; }
      const cat = catOf(c1), lr = ladder(cat).find(r => r[0] === c1.slice(cat.length + 1));
      results[`${cat} ${lr[1]}`] = s1 > s2 ? { winner: p1, loser: p2 } : { winner: p2, loser: p1 };
      for (const [code, p, a, b] of [[c1, p1, s1, s2], [c2, p2, s2, s1]]) {
        const r = ladder(cat).find(x => x[0] === code.slice(cat.length + 1));
        playoffRows[code] = [code, p[0], p[1], a > b ? 1 : 0, a > b ? 0 : 1, (a / Math.max(b, 1)).toFixed(4), '', r[1], r[2] || '', r[3] || ''];
      }
    }
  }

  // STANDINGSCSV, as the workbook writes it: each category's pairs, then its ladder's seats.
  const standings = [];
  for (const cat of Object.keys(cats)) {
    for (const code of Object.keys(names).filter(k => catOf(k) === cat)) {
      const r = rec[code];
      standings.push([code, names[code][0], names[code][1], r.w, r.l, (r.pf / r.pa).toFixed(4), bracketOf[code], '', '', '']);
    }
    for (const [slot, match, from = '', seat = ''] of ladder(cat)) {
      const code = `${cat}_${slot}`;
      if (playoffRows[code]) { standings.push(playoffRows[code]); continue; }
      const p = seatNames(code);
      standings.push([code, p[0], p[1], 0, 0, '0.0000', '', match, from, seat]);
    }
  }

  const csv = table => table.map(r => r.map(v => /[,"]/.test(String(v)) ? `"${v}"` : v).join(',')).join('\r\n');
  const matchesCsv = csv([['matchNumber', 'court', 'Schedule', 'CourtAssignment', 'teamCode1', 'team1Player1', 'team1Player2', 'team1Score', 'teamCode2', 'team2Player1', 'team2Player2', 'team2Score'], ...rows]);
  const standingsCsv = csv([['teamCode', 'player1', 'player2', 'wins', 'loss', 'quotient', 'bracket', 'match', 'from', 'seat'], ...standings]);
  const at = day.endsWith('1') ? '2026-11-28T09:30:00.000Z' : '2026-11-29T08:00:00.000Z';
  const snapshot = {
    day, label, isLive: true, generatedAt: at, publishedAt: at,
    facilities: [{ name: FACILITY, matchesCsv, standingsCsv, syncedAt: at, lastEditAt: at }],
    failedFacilities: [], staleFacilities: [],
  };
  const podium = cat => {
    const f = results[`${cat} F`], b = results[`${cat} B`];
    const bronze = b ? b.winner : seatNames(`${cat}_B_1`);
    return `${cat} ${f.winner[0].trim()}/${bronze[0].trim()}`;
  };
  const summary = `${rows.length} matches, ${Object.keys(names).length} pairs; gold/bronze ${Object.keys(cats).map(podium).join(', ')}`;
  return { snapshot, summary };
}
