    1.1 Format and scoring — the organiser's¶

    From the organiser's sheet, sent 18 October 2026:

    • Format. A single round robin, every team against every other. Each team's captain chooses its doubles pairs per category for each round, submitted to match control round by round, and a pair may not be repeated after a round. The four teams with the most wins go on: 3rd and 4th play for 3rd place, 1st and 2nd play for 2nd place and overall champion.
    • Ranking. Teams are ranked by number of wins: the games they have won in the round robin.
    • Ties, among teams level on wins, as revised on 20 October 2026:
    • two teams (a double tie):
      1. head-to-head wins, the games each won in their matchup;
      2. still level: the head-to-head quotient, points for ÷ points against in those games;
      3. still level: the teams submit lineups and one pair from each plays one game to 5.
    • three or more (a triple tie or more):
      1. the quotient, points for ÷ points against over all their round-robin games;
      2. two teams with exactly the same quotient go to the double-tie rules;
      3. three or more with the same quotient submit lineups, and one pair from each plays a round robin of games to 5.

    The site ranks by every step it can compute. A tie only a playoff can settle keeps the workbook's order, and once the bracket's round robin is over its teams share the higher rank and read Tied · playoff game or Tied · playoff round robin. The organiser settles it by typing the qualifiers into the playoff slots, as for every playoff (§4.3); nothing records the playoff's result.

    The organiser's first sheet gave point differential, then head-to-head wins; the owner's revision of 18 October 2026 gave total points, head-to-head wins and head-to-head points (§17 Q2). The 20 October rules above replace both.

    The site shows none of these: the two sponsorship phone numbers, the Plus 63 club logo, the pubmat's ball and court artwork. The site is a live results hub for players who have already entered.

    4. Engine change — teamScoring: "games"¶

    A team event may set "teamScoring": "games" in events.json. Absent (or "points"), everything behaves exactly as today. With "games":

    • a matchup is won by the side that won more of its games. Level on games, the side with more total points wins, the organiser's first tiebreaker. Still level, it is a tie, shown as today (§17 Q3);
    • a bracket is ranked by games won, then the tiebreakers of §1.1: for two teams level, head-to-head wins and the head-to-head quotient; for three or more, the overall quotient, two still level going to the two-team rules. A tie left after that keeps the sheet's order and, once the round robin is over, reads Tied (teamRankBracket's result carries it as ties). Only played group-stage games count, all computed from the matches, so every key comes from the same scores. The code listings below show the first version of the ranking (total points, head-to-head wins, head-to-head points), which these rules replace;
    • the bracket table shows W, L and Pts (total points won) instead of PF, PA and Quotient, and a matchup's headline score is its games (3 – 1), with the points underneath.

    A game counts as won by the side with the higher score once both scores are in (the played rule of lib/v1/domain/matches.js). Equal scores count for neither side. The awards podium needs no edit: it reads each matchup's result.winner.

    /**
 * Each side's record in the day's played group-stage matches, for "games"
 * scoring: matches won and lost, and points for and against. A match with equal
 * scores counts for neither side's W or L.
 * @param {object[]} matches  the day's matches
 * @returns {Map<string, { won:number, lost:number, pf:number, pa:number }>}  keyed by side
 */
export function teamGameRecords(matches){
  const out = new Map();
  const rec = side => {
    if(!out.has(side)) out.set(side, { won: 0, lost: 0, pf: 0, pa: 0 });
    return out.get(side);
  };
  matches.forEach(m => {
    if(!m.played || stageOf(sideOf(m.t1)) !== null) return;
    const a = rec(sideOf(m.t1)), b = rec(sideOf(m.t2));
    a.pf += m.t1Score; a.pa += m.t2Score;
    b.pf += m.t2Score; b.pa += m.t1Score;
    if(m.t1Score > m.t2Score){ a.won++; b.lost++; }
    else if(m.t2Score > m.t1Score){ b.won++; a.lost++; }
  });
  return out;
}

        if(!codes.has(s1) || !codes.has(s2)) return;

        (h2hWins.get(b.teamCode) - h2hWins.get(a.teamCode)) ||
        (h2hPts.get(b.teamCode) - h2hPts.get(a.teamCode)));
    }
    out.push(...tied);
    i = j;
  }
  return out;
}

    18. Decisions, for reference¶

    • Scoring is an engine option, not a fork. The rule lives in lib/v1/domain/teams.js, which the Hub, the board, Control Center and its Awards podium all share, so one option corrects all of them. It is opt-in per event (teamScoring), defaulting to PickleDrive's rule, so no other page changes, and it is a compatible v1 change (§4.8), not a v2.
    • Tiebreakers: the organiser's double-tie and triple-tie rules of 20 October 2026 (§1.1), which replace the owner's revision of 18 October (total points, head-to-head wins, head-to-head points) and the organiser's first sheet. The triple-tie quotient is each team's overall one; only two teams with exactly the same quotient go to the double-tie rules; a tie that needs a playoff is flagged, not resolved, and the workbook's playoff slots settle it.
    • Ranking is computed from the matches. STANDINGSCSV publishes points, not games, and changing its columns would touch every team page's reader. The matches already carry every score the rule needs.
    • A 2–2 playoff matchup goes to total points, the organiser's first tiebreaker (§17 Q3, confirmed).
    • Event key millennium-invitational-2026, day key millennium-invitational-2026-day1. The club's name plus the event's own, following pickledrive-anniversary-2026. The day key carries the event key because day keys must be globally unique (§14).
    • Title "Millennium Pickleball Club", the event in the hero. The owner's choice. The hero says "2nd Invitational Tournament / Paying It Forward!", and no ordinal goes in the <title> or the Control Center masthead, where it would date next year's page, as decided for Piggleball.
    • Every team has a name, the colour by default. The engine shows a playoff qualifier by its team's name and reads a nameless one as a seed still to be decided, so a name is required; the colour is the name when the organiser has no other. This needs no engine change.
    • The colours are the team codes. The workbook already uses Red_1 …, and the engine takes any text before _ as the side, so nothing in the sheet is re-coded to letters.
    • Gold in the fill role, the logo's green in the text role. The template's accent fill sits under navy text and on navy panels; gold passes there (12.11:1). The logo green passes as text on cream and under white text, which is the other role. The pubmat's lime is used once, for the headline, as on the pubmat.
    • Cream paper, from the logo. The pubmat's own ground is the court artwork, not a flat colour. The logo's cream keeps the page warm against the dark green hero.
    • The hero stays dark. The pubmat's panels are dark green, and the template's hero controls are styled for a dark panel.
    • Engine colour overrides live in the shell. lib/v1/css/ hard-codes some house colours. Fixing that in the engine (tokens for every tint) is another engine change days before an event, for looks only. A shell override is local, freezes with the event, and repeats only selectors the versioning rule already promises not to rename. The engine fix is worth doing after the event, so the next re-skin doesn't repeat §9.3.
    • "Seed 1" is the better-placed team. Before the qualifiers are typed, the Hub shows Seed 1 · TBD. Making Br-1 the 3rd-placed team keeps that label true; the organiser's schedule listing the Bronze as "4th vs 3rd" is order only.
    • Logo cropped, pubmat not loaded. The badge filled 41% of the supplied image, so it is cropped to the circle. The pubmat stays in assets/ as the colour and font reference, as at Piggleball.
    • No sponsor phone numbers or partner logo. The phone numbers are for sponsorship enquiries, not for players. The hero pairs only the organiser's logo with S.A.G.E.'s, as on every event.

    Appendix A — the fixture script¶

    Used by §13 only, and never committed. Save it outside the repo and run it from the site repo root. It writes _fixtures/millennium-invitational-2026/finished.json and adds the event to _fixtures/config.json; §13.4 removes both.

    // Writes a temporary, local-only fixture for the Millennium Invitational, shaped like the real event: 8 colour
// teams in one bracket, a full round robin of 4-game matchups on 8 courts from 1:00 PM, then a Bronze and a Final
// seeded by the "games" ranking. Each team is named after its colour, as the spec's §16.1 asks of a team with no
// other name. Every match is played, with fixed made-up scores and player names.
//   _fixtures/millennium-invitational-2026/finished.json   the snapshot
//   _fixtures/config.json                                  gains a "millennium-invitational-2026" entry
// Neither is ever committed. Undo with:
//   git checkout -- _fixtures/config.json && rm -rf _fixtures/millennium-invitational-2026
// usage, from the site repo root: node <path>/make-millennium-fixture.mjs
import fs from 'node:fs';
import path from 'node:path';

const EVENT = 'millennium-invitational-2026', DAY = 'millennium-invitational-2026-day1';
const TEAMS = ['Red', 'Orange', 'Yellow', 'Green', 'Blue', 'Purple', 'Sky', 'Pink'];

// Fixed pseudo-random scores: the same file every run.
let seed = 20261024;
const rand = n => { seed = (seed * 1103515245 + 12345) % 2147483648; return Math.floor(seed / 65536) % n; };
const game = () => { const loser = rand(10); return rand(2) ? [11, loser] : [loser, 11]; };
const player = (team, n) => `${team} Player ${n}`;
const time = slot => { const min = 13 * 60 + 30 * slot; const h = Math.floor(min / 60); return `${h > 12 ? h - 12 : h}:${String(min % 60).padStart(2, '0')} PM`; };

// Round robin by the circle method: 7 rounds of 4 matchups. Each round is two slots: pairs 1-2, then pairs 3-4.
const rounds = [];
const circle = TEAMS.slice();
for (let r = 0; r < 7; r++) {
  rounds.push([0, 1, 2, 3].map(i => [circle[i], circle[7 - i]]));
  circle.splice(1, 0, circle.pop());
}
const rows = [];
let num = 0;
const addMatchup = (side1, side2, slot, pairs, courtOf, scores) => pairs.forEach((p, k) => {
  const [s1, s2] = scores ? scores[k] : game();
  const base = s => s.replace(/^(Br|Fi)-/, '');
  rows.push([++num, `${side1} v ${side2}`, '', time(slot), `Court ${courtOf(k)}`,
    `${side1}_${p}`, player(base(side1), 2 * p - 1), player(base(side1), 2 * p), s1,
    `${side2}_${p}`, player(base(side2), 2 * p - 1), player(base(side2), 2 * p), s2]);
});
rounds.forEach((round, r) => {
  [[1, 2], [3, 4]].forEach((pairs, half) =>
    round.forEach(([a, b], i) => addMatchup(a, b, 2 * r + half, pairs, k => 2 * i + k + 1)));
});

// Rank by the event's rules (games won, total points; the fixed scores leave no deeper ties to break).
const rec = Object.fromEntries(TEAMS.map(t => [t, { won: 0, pf: 0, pa: 0 }]));
for (const row of rows) {
  const [a, b] = [row[5].split('_')[0], row[9].split('_')[0]];
  rec[a].pf += row[8]; rec[a].pa += row[12]; rec[b].pf += row[12]; rec[b].pa += row[8];
  if (row[8] > row[12]) rec[a].won++; else rec[b].won++;
}
const ranked = TEAMS.slice().sort((x, y) => rec[y].won - rec[x].won || rec[y].pf - rec[x].pf);
// The Bronze, then the Final, with the qualifiers typed over the seeds (§16.4). The Final's side 1 wins three
// games on fewer points, so the games rule visibly decides it.
addMatchup(`Br-${ranked[2]}`, `Br-${ranked[3]}`, 14, [1, 2, 3, 4], k => k + 1);
addMatchup(`Fi-${ranked[0]}`, `Fi-${ranked[1]}`, 15, [1, 2, 3, 4], k => k + 1, [[11, 9], [11, 9], [11, 9], [2, 11]]);

const csv = table => table.map(r => r.join(',')).join('\r\n');
const matchesCsv = csv([['matchNumber', 'matchUp', 'court', 'Schedule', 'CourtAssignment', 'teamCode1', 'team1Player1', 'team1Player2', 'team1Score', 'teamCode2', 'team2Player1', 'team2Player2', 'team2Score'], ...rows]);
const standingsCsv = csv([['teamCode', 'teamName', 'totalPoints', 'totalOpponentPoints', 'quotient', 'bracket'],
  ...TEAMS.map(t => [t, t, rec[t].pf, rec[t].pa, (rec[t].pf / rec[t].pa).toFixed(5), 1]),
  ['Br-1', '', 0, 0, '-', ''], ['Br-2', '', 0, 0, '-', ''], ['Fi-1', '', 0, 0, '-', ''], ['Fi-2', '', 0, 0, '-', '']]);
const rosterCsv = csv([['teamCode', 'player', 'level', 'gender'],
  ...TEAMS.flatMap(t => [1, 2, 3, 4, 5, 6, 7, 8].map(n => [t, player(t, n), '', n <= 4 || n === 7 ? 'M' : 'F']))]);

const snapshot = {
  day: DAY, label: 'Oct 24', isLive: true,
  generatedAt: '2026-10-24T13:00:00.000Z', publishedAt: '2026-10-24T13:00:00.000Z',
  facilities: [{ name: 'Plus 63', matchesCsv, standingsCsv, rosterCsv, syncedAt: '2026-10-24T13:00:00.000Z', lastEditAt: '2026-10-24T13:00:00.000Z' }],
  failedFacilities: [], staleFacilities: [],
};
fs.mkdirSync(path.join('_fixtures', EVENT), { recursive: true });
fs.writeFileSync(path.join('_fixtures', EVENT, 'finished.json'), JSON.stringify(snapshot, null, 2) + '\n');

const configPath = path.join('_fixtures', 'config.json');
const config = JSON.parse(fs.readFileSync(configPath, 'utf8'));
config.events[EVENT] = {
  type: 'team', title: 'Millennium Pickleball Club', teamScoring: 'games', attendance: 'desks', scoreEntry: 'links',
  days: { [DAY]: { label: 'Oct 24', date: '2026-10-24', isLive: 'auto', facilities: [{ name: 'Plus 63', sheetId: 'FIXTUREMILLENNIUMSHEETID000000000' }] } },
  display: { pairs: {
    1: { full: "Men's Doubles", short: 'MD' }, 2: { full: "Men's Doubles", short: 'MD' },
    3: { full: "Women's Doubles", short: 'WD' }, 4: { full: 'Mixed Doubles', short: 'XD' },
  } },
};
fs.writeFileSync(configPath, JSON.stringify(config, null, 2) + '\n');
console.log(`${rows.length} matches; ranking ${ranked.map(t => `${t} ${rec[t].won}W ${rec[t].pf}pts`).join(', ')}`);
console.log(`Final: Fi-${ranked[0]} v Fi-${ranked[1]}; Bronze: Br-${ranked[2]} v Br-${ranked[3]}`);
