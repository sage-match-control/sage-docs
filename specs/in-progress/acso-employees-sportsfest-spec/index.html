    Spec — Angeles City Employees Sportsfest Pickleball Tournament¶

    Status: in progress. Written 2026-10-21 against sage-match-control.github.io at 9f6717d, event-data's current config/events.json, and the event workbook as exported that day. The owner answered every open question the same day; the answers are in §17.

    Built and pushed, 2026-10-21: §4–§10 (the event's pages, with the logo) are on the site's main (75c3e42), and §14's events.json entry is in event-data's main. The workbook syncs (§16.2): its snapshot lists Pickle Place with all 96 matches and the players' names, so §16.1's items 1 and 3 are done. Still to do: assets/qr.png (§2) and the QR panel (§16.4), the rest of §16.1 (the Court Control check, the start time and the players in two categories), the playoff draw on the day, and the dry run (§16.5).

    Dry-run on 2026-10-21. §4–§9 were applied to a detached worktree of the site at 9f6717d: every anchor matched once and every check passed. §11's fixture was built and the Hub, the board, Control Center and the desk page were checked in a browser at 375px, 1280px and 1440px; §11.3 is what they showed. §12's npm run verify and §14 were not run.

    Deadline. The event is on Friday 13 November 2026, and the site repo takes no merge within 3 days of an event. The pages reach the site's main by Monday 9 November. After that, push only with the owner's go-ahead.

    Build the event site for the Angeles City Employees Sportsfest Pickleball Tournament, a one-day tournament for Angeles City government employees on Friday 13 November 2026, 8:00 AM to 5:00 PM, at Pickle Place. The organiser is the Angeles City Sports Office (ACSO).

    The Sportsfest also has other sports (the ACSO logo shows volleyball, basketball, boxing and swimming). They are out of scope. The site covers only the pickleball tournament.

    The site is an instance of _templates/standard-tournament-template/, the third "standard" event after Pickle for Sight and Piggleball, and the first made from the template since the site engine replaced the pages' configuration blocks. It needs no engine change: the one unusual thing about this event, team codes without a division (§3), is handled by the event's events.json entry alone.

    There is no pubmat, so the site keeps the S.A.G.E. house theme: no colour or font changes anywhere. The only colours this spec sets are the schedule board's category colours, which are the organiser's own (§7).

    The runbook for instantiating a template is sage-match-control.github.io/_templates/CLAUDE.md. This spec gives every value and every edit, so you should not need to make any design decisions. If this spec and the runbook disagree, stop and ask. Don't pick one.

    0. How to use this spec¶

    You can carry this out with no other context: every value, every edit and every check is here. Read §0 to §3 before you change anything.

    0.1 Rules¶

    • Find edits by their anchor text, not line numbers. Every edit quotes the exact text to find, and each anchor occurs once in its file. If an anchor isn't there, or is there twice, stop and report. Don't guess.
    • Every anchor is a single line. The site checkout has Windows line endings (CRLF, from core.autocrlf), so a multi-line search can miss text that looks identical. Keep the files' line endings as they are.
    • Use Git Bash for the commands and checks. Python is not installed on this machine; Node is (22.23.3 or later).
    • Edit only events/acso-sportsfest-2026/ in the site repo, and only config/events.json in event-data. Don't edit lib/, tools/, _templates/, _tests/ or any other event's folder. If something there seems to need a change, stop and report it.
    • Don't change the theme. Leave every :root block, font link and colour in the copied pages exactly as the template has them (§8).
    • Commit where §0.3 says commit, with a plain message saying what changed, ending with the attribution line your session's instructions give.
    • Never push, and never merge into main, without the owner's yes in chat. Pushing the site's main publishes it; pushing event-data's main registers the event with the live API. §0.3 marks where you stop and ask.
    • Don't rename, "fix" or tidy anything this spec doesn't mention.

    3. How this event differs from Piggleball¶

    Piggleball was the last standard event. Four differences matter:

    1. The pages are shells now. Piggleball's spec filled in DAYS, FACILITIES, DIVISIONS and EVENTS arrays inside index.html. Those are gone: the Hub reads its days, facility and labels from events.json (§14). There is no configuration block to fill in.
    2. No re-skin. No pubmat, so no palette, font or hero-style changes (§8).
    3. No divisions. Every team code is <EVENT>_<REST> (MD_1, WD_SF_2, XD_QF_7), where earlier events had <DIVISION><EVENT>_<REST> (IMD_1). The engine splits a category token by matching display.divisions' keys as prefixes, then looks the remainder up in display.events. An empty-string division key, "divisions": { "": "" }, matches every token as a prefix and leaves the whole token (MD) as the event code, so MD reads "Men's Doubles": the division label is empty and the engine trims the space. Checked against lib/v1/domain/codes.js and lib/v1/domain/attendance.js (categoryLabel, buildCategoryOrderIndex, defaultCategoryLabel): MD_1, WD_SF_2, XD_QF_7 label as "Men's Doubles", "Women's Doubles", "Mixed Doubles", order MD, WD, XD, with no Unmapped category warning. Without that key the pages still work but show the raw codes MD, WD, XD. Don't drop it, and don't invent a division name.
    4. Eight courts, so the schedule board has eight columns.

    16.1 Workbook fixes before sync setup¶

    The workbook was generated from the Standard Tournament Master, so its tabs, codes and column names match what the site reads. The ATTENDANCE tab has its header. What is left:

    1. CSV lists only match 1. Rows 3–97 hold the match numbers 2–96 but every other column is blank, so the site would show one match. SAGE → Fill match numbers writes the numbers into CSV!A and copies CSV row 2's formulas down a row per match; this time the copy didn't happen. Re-run SAGE → Fill match numbers, starting after 0. If the rows are still blank, copy CSV!B2:L2 and paste it into B3:L97. Check: CSV has 96 rows, and row 97 reads match 96, 2:00 PM, Court 7, XD_B_1 against XD_B_2.
    2. Court Control shows #REF! on all 8 courts. As at Piggleball, that may be only because no match is on court yet, or a broken formula. The Live board reads CSV's court column, which Court Control feeds, so test it: put a match on Court 1 the way operators will on the day, confirm the #REF! clears and that match's court cell in CSV fills in.     3. Rosters aren't in yet. Every pair still shows its code (MD_1, …) as its player name. Paste the names into each category tab (MD, WD, XD), then run Update roster for the ATTENDANCE tab from Control Center.
    4. The playoff draw. Each category tab has a "place 1st playoffs bunutan here" block that seats the bracket qualifiers in the SF (MD, WD) or QF (XD) slots. It is done on the day, after the round robin.
    5. Start time. The organiser's hours are 8:00 AM to 5:00 PM; the workbook's first match is 9:00 AM and its last at 2:00 PM. Confirm 9:00 AM with the organiser (8:00 AM is presumably arrival and the opening). The site's go-live reads the workbook, not the hours.
    6. Tight playoffs — the organiser's call. The MD and WD semifinals (1:10 PM) follow the last round-robin slot (12:45 PM) directly, with no slot free for the draw, and each Final follows its semifinal directly (1:35 PM); XD plays quarterfinal, semifinal and Final in three consecutive slots. The site shows whatever the workbook says, so nothing here needs changing unless the organiser wants rest.
    7. Players in two categories. MD, WD and XD run side by side all morning, so an employee entered in MD or WD and also in XD can be due on two courts in the same slot. Timeline only catches the same pair twice in a slot. Once names are in (item 3), look for any name in both XD and one of the others, and check their slots.

    18. Decisions, for reference¶

    • Event key acso-sportsfest-2026, day key acso-sportsfest-day1. Short, carry the organiser's own acronym (the big word on its logo), and the day key has an event prefix because day keys must be globally unique (§14).
    • Title "Angeles City Employees Sportsfest Pickleball". The tournament's own name, not the Sportsfest's, because the site covers only the pickleball (as Piggleball's title was the tournament's, not the Pig Sports Festival's). It drops the trailing "Tournament", which would read twice in the browser tab's "… Tournament — Tournament Hub". The footer gives the full name.
    • Hero split across tagline, title and headline (§6.2): the full title in the hero's display type would take four lines on a phone.
    • Empty division key (§3 item 3), not a made-up division like "Open": the organiser has no divisions, and an invented label would show on every card.
    • House theme. No pubmat, so no re-skin. The ACSO logo is shown as supplied; its red, yellow, green and blue are not lifted into the palette, because that would be a re-skin from a logo alone, which no event has done.
    • The board's colours are the organiser's (§7), so the wall display matches the printed schedule, as at every standard event.
    • No hours on the page. The organiser's 8:00 AM–5:00 PM would sit next to match times starting at 9:00 AM and confuse players; the Hub's times come from the workbook.

    Appendix A — the fixture script¶

    Used by §11 only, and never committed. Save it outside the repo and run it from the site repo root. It writes _fixtures/acso-sportsfest-2026/finished.json and adds the event to _fixtures/config.json; §11.4 removes both.

    // Writes a temporary, local-only fixture for the Angeles City Employees Sportsfest, shaped like the real event:
// the workbook's own SCHEDULE (96 matches on 8 courts, 9:00 AM to 2:00 PM), MD and WD in two round-robin brackets
// of 5 then semifinals, Bronze and Final, XD in four brackets of 5 then quarterfinals, semifinals, Bronze and Final.
// Every match is played, with fixed made-up scores and player names.
//   _fixtures/acso-sportsfest-2026/finished.json   the snapshot
//   _fixtures/config.json                          gains an "acso-sportsfest-2026" entry
// Neither is ever committed. Undo with:
//   git checkout -- _fixtures/config.json && rm -rf _fixtures/acso-sportsfest-2026
// usage, from the site repo root: node <path>/make-acso-fixture.mjs
import fs from 'node:fs';
import path from 'node:path';

const EVENT = 'acso-sportsfest-2026', DAY = 'acso-sportsfest-day1';

// The workbook's SCHEDULE, slot by slot: each slot lists Court 1, Court 2, … in order, '-' for an empty court.
const SLOTS = [
  ['9:00 AM',  'MD_1:MD_2 MD_3:MD_4 WD_1:WD_2 WD_3:WD_4 XD_1:XD_2 XD_3:XD_4 XD_6:XD_7 XD_8:XD_9'],
  ['9:25 AM',  'MD_6:MD_7 MD_8:MD_9 WD_6:WD_7 WD_8:WD_9 XD_11:XD_12 XD_13:XD_14 XD_16:XD_17 XD_18:XD_19'],
  ['9:50 AM',  'MD_1:MD_3 MD_4:MD_5 WD_1:WD_3 WD_4:WD_5 XD_1:XD_3 XD_4:XD_5 XD_6:XD_8 XD_9:XD_10'],
  ['10:15 AM', 'MD_6:MD_8 MD_9:MD_10 WD_6:WD_8 WD_9:WD_10 XD_11:XD_13 XD_14:XD_15 XD_16:XD_18 XD_19:XD_20'],
  ['10:40 AM', 'MD_1:MD_4 MD_2:MD_5 WD_1:WD_4 WD_2:WD_5 XD_1:XD_4 XD_2:XD_5 XD_6:XD_9 XD_7:XD_10'],
  ['11:05 AM', 'MD_6:MD_9 MD_7:MD_10 WD_6:WD_9 WD_7:WD_10 XD_11:XD_14 XD_12:XD_15 XD_16:XD_19 XD_17:XD_20'],
  ['11:30 AM', 'MD_3:MD_5 MD_2:MD_4 WD_3:WD_5 WD_2:WD_4 XD_3:XD_5 XD_2:XD_4 XD_8:XD_10 XD_7:XD_9'],
  ['11:55 AM', 'MD_8:MD_10 MD_7:MD_9 WD_8:WD_10 WD_7:WD_9 XD_13:XD_15 XD_12:XD_14 XD_18:XD_20 XD_17:XD_19'],
  ['12:20 PM', 'MD_1:MD_5 MD_2:MD_3 WD_1:WD_5 WD_2:WD_3 XD_1:XD_5 XD_2:XD_3 XD_6:XD_10 XD_7:XD_8'],
  ['12:45 PM', 'MD_6:MD_10 MD_7:MD_8 WD_6:WD_10 WD_7:WD_8 XD_11:XD_15 XD_12:XD_13 XD_16:XD_20 XD_17:XD_18'],
  ['1:10 PM',  'MD_SF_1:MD_SF_2 MD_SF_3:MD_SF_4 WD_SF_1:WD_SF_2 WD_SF_3:WD_SF_4 XD_QF_1:XD_QF_2 XD_QF_3:XD_QF_4 XD_QF_5:XD_QF_6 XD_QF_7:XD_QF_8'],
  ['1:35 PM',  'MD_F_1:MD_F_2 MD_B_1:MD_B_2 WD_F_1:WD_F_2 WD_B_1:WD_B_2 XD_SF_1:XD_SF_2 - XD_SF_3:XD_SF_4 -'],
  ['2:00 PM',  '- - - - XD_F_1:XD_F_2 - XD_B_1:XD_B_2 -'],
];
const CATS = { MD: { name: 'Men', pairs: 10, brackets: 2 }, WD: { name: 'Women', pairs: 10, brackets: 2 }, XD: { name: 'Mixed', pairs: 20, brackets: 4 } };

// Fixed pseudo-random scores: the same file every run.
let seed = 20261113;
const rand = n => { seed = (seed * 1103515245 + 12345) % 2147483648; return Math.floor(seed / 65536) % n; };
const score = () => { const loser = rand(10); return rand(2) ? [11, loser] : [loser, 11]; };

// A pair's players, like the workbook's (each name ends in a space). Playoff slots take their qualifier's names.
const names = {};
for (const [cat, c] of Object.entries(CATS)) {
  for (let n = 1; n <= c.pairs; n++) names[`${cat}_${n}`] = [`${c.name} ${n}A `, `${c.name} ${n}B `];
}
const bracketOf = code => Math.ceil(Number(code.split('_')[1]) / 5);

const rec = {};   // code -> { w, l, pf, pa }
const tally = (code, pf, pa) => {
  const r = rec[code] || (rec[code] = { w: 0, l: 0, pf: 0, pa: 0 });
  r.pf += pf; r.pa += pa; if (pf > pa) r.w++; else r.l++;
};
const winnerOf = {}, loserOf = {};   // "MD_SF_1:MD_SF_2" -> the winning / losing pair's names
const rows = [];
let num = 0;

// Rank a category's round-robin bracket: wins, then points quotient.
const ranked = (cat, b) => Object.keys(rec).filter(k => k.startsWith(cat + '_') && /^[A-Z]+_\d+$/.test(k) && bracketOf(k) === b)
  .sort((x, y) => rec[y].w - rec[x].w || rec[y].pf / rec[y].pa - rec[x].pf / rec[x].pa);
// Who fills each playoff slot once the stage before it is over (the organiser's draw, fixed here).
const seat = (cat, code) => {
  const rest = code.slice(cat.length + 1);
  const top = (b, i) => names[ranked(cat, b)[i]];
  if (CATS[cat].brackets === 2) {
    if (rest.startsWith('SF_')) return { SF_1: top(1, 0), SF_2: top(2, 1), SF_3: top(2, 0), SF_4: top(1, 1) }[rest];
  } else {
    if (rest.startsWith('QF_')) return { QF_1: top(1, 0), QF_2: top(2, 1), QF_3: top(2, 0), QF_4: top(1, 1),
      QF_5: top(3, 0), QF_6: top(4, 1), QF_7: top(4, 0), QF_8: top(3, 1) }[rest];
    if (rest.startsWith('SF_')) { const k = Number(rest.slice(3)); return winnerOf[`${cat}_QF_${2 * k - 1}:${cat}_QF_${2 * k}`]; }
  }
  const sf = k => `${cat}_SF_${2 * k - 1}:${cat}_SF_${2 * k}`;
  return { F_1: winnerOf[sf(1)], F_2: winnerOf[sf(2)], B_1: loserOf[sf(1)], B_2: loserOf[sf(2)] }[rest];
};

const playoffRows = [];
SLOTS.forEach(([time, courts]) => {
  courts.split(' ').forEach((pair, i) => {
    if (pair === '-') return;
    const [c1, c2] = pair.split(':');
    const cat = c1.split('_')[0];
    const isPlayoff = !/^[A-Z]+_\d+$/.test(c1);
    const p1 = isPlayoff ? seat(cat, c1) : names[c1], p2 = isPlayoff ? seat(cat, c2) : names[c2];
    const [s1, s2] = score();
    rows.push([++num, '', time, `Court ${i + 1}`, c1, p1[0], p1[1], s1, c2, p2[0], p2[1], s2]);
    if (isPlayoff) {
      winnerOf[pair] = s1 > s2 ? p1 : p2; loserOf[pair] = s1 > s2 ? p2 : p1;
      playoffRows.push([c1, p1[0], p1[1], s1 > s2 ? 1 : 0, s1 > s2 ? 0 : 1, (s1 / Math.max(s2, 1)).toFixed(4), '']);
      playoffRows.push([c2, p2[0], p2[1], s2 > s1 ? 1 : 0, s2 > s1 ? 0 : 1, (s2 / Math.max(s1, 1)).toFixed(4), '']);
    } else { tally(c1, s1, s2); tally(c2, s2, s1); }
  });
});

const csv = table => table.map(r => r.join(',')).join('\r\n');
const matchesCsv = csv([['matchNumber', 'court', 'Schedule', 'CourtAssignment', 'teamCode1', 'team1Player1', 'team1Player2', 'team1Score', 'teamCode2', 'team2Player1', 'team2Player2', 'team2Score'], ...rows]);
const rrRows = Object.keys(names).map(code => { const r = rec[code];
  return [code, names[code][0], names[code][1], r.w, r.l, (r.pf / r.pa).toFixed(4), bracketOf(code)]; });
const standingsCsv = csv([['teamCode', 'player1', 'player2', 'wins', 'loss', 'quotient', 'bracket'], ...rrRows, ...playoffRows]);

const at = '2026-11-13T06:40:00.000Z';
const snapshot = {
  day: DAY, label: 'Nov 13', isLive: true, generatedAt: at, publishedAt: at,
  facilities: [{ name: 'Pickle Place', matchesCsv, standingsCsv, syncedAt: at, lastEditAt: at }],
  failedFacilities: [], staleFacilities: [],
};
fs.mkdirSync(path.join('_fixtures', EVENT), { recursive: true });
fs.writeFileSync(path.join('_fixtures', EVENT, 'finished.json'), JSON.stringify(snapshot, null, 2) + '\n');

const configPath = path.join('_fixtures', 'config.json');
const config = JSON.parse(fs.readFileSync(configPath, 'utf8'));
config.events[EVENT] = {
  type: 'standard', title: 'Angeles City Employees Sportsfest Pickleball', attendance: 'desks', scoreEntry: 'console',
  days: { [DAY]: { label: 'Nov 13', date: '2026-11-13', isLive: 'auto', facilities: [{ name: 'Pickle Place', sheetId: 'FIXTUREACSOSHEETID0000000000000000' }] } },
  display: { divisions: { '': '' }, events: { MD: "Men's Doubles", WD: "Women's Doubles", XD: 'Mixed Doubles' } },
};
fs.writeFileSync(configPath, JSON.stringify(config, null, 2) + '\n');

const champ = cat => `${cat} ${winnerOf[`${cat}_F_1:${cat}_F_2`][0].trim()}`;
console.log(`${rows.length} matches, ${rrRows.length} pairs; champions ${['MD', 'WD', 'XD'].map(champ).join(', ')}`);
