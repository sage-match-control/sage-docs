    1. Orientation — read this first¶

    1.1 The repos¶

    1.2 What exists today, in one paragraph¶

    A tournament day runs from a Google Sheets workbook, one per venue per day, which sage-tools-api syncs into a JSON snapshot holding two CSV strings per venue: the CSV tab (every match) and the STANDINGSCSV tab (one row per pair and per playoff slot). Every page reads that snapshot. The site's pages are plain ES modules with no build step. The shared code is the engine in lib/v1/, which has four layers:

    • domain/: pure rules.
    • data/: fetching.
    • views/: HTML-string builders and small components.
    • apps/: one per page kind.

    The Hub (lib/v1/apps/hub.js) and Control Center (tools/control-center.html) both draw a standard event's standings with createStandings in lib/v1/views/standings.js. Each category is one card: its round robin tables, then one block per playoff stage, each a list of matchup cards. This spec adds a second way to draw the playoff blocks.

    1.3 Rules you must follow¶

    • lib/v1 takes compatible changes only. You may add a module, an export, an option, a CSS class or a field. You may not remove or rename one, or change a parameter or return shape an existing caller would notice.
    • Within one push, a module may use another module's new export. A module may not start using an export that an earlier push did not publish, because browsers cache files for up to 10 minutes. This spec's site work is one push, so that's fine.
    • See sage-docs/docs/technical/site-engine.md § "The versioning rule".
    • Dependency rules, enforced by _tests/unit/guards.test.mjs:
    • domain/ imports only domain/.
    • views/ imports domain/ and views/.
    • Nothing under views/ or domain/ knows about operators: Control Center adds its behaviour through an option that does nothing by default (§7.9).
    • The theme contract (_tests/unit/theme-contract.test.mjs): engine CSS takes its colours only from the shell's custom properties. Use the --… names listed in that test. The rgba(…) literals already used by .matchup-side.win and .matchup-side.loss in lib/v1/css/standings.css may be reused as they are.
    • apps-script/ is not part of the Cloud Run service.
    • Changing the generator bumps STANDARD_TOURNAMENT_GENERATOR_VERSION and its history comment, not package.json.
    • Run node apps-script/verify-standard-tournament-generator.mjs and npm run verify in sage-tools-api before pushing.
    • A push to sage-tools-api's main triggers a Cloud Run redeploy of unchanged service code. That's harmless, but push only with the owner's go-ahead.
    • The site:
    • Run cd _tests && npm install && npm run verify before every push to main.
    • Never merge within 3 days of an event (see the deadlines at the top).
    • Work on a branch. Don't push to main without the owner.
    • Docs are written in the present tense (what the system does), never "now" or "used to".

    5. Workbook: two new STANDINGSCSV columns¶

    5.1 The columns¶

    STANDINGSCSV keeps its seven columns A:G exactly as they are. The generator adds two:

    Col Header Value on a playoff slot's row On a round robin row
    H match The block label of the match this slot plays in, exactly as the category tab's playoff block reads: R16-3, QF-2, SF-1, F, B, F (1), F (2), F (3) empty
    I from W:<block label> when the winner of that match fills this slot, L:<block label> when its loser does, and empty when the slot is filled from the round robin (the draw, a fixed seat or a bye) empty

    Why match and not seat numbers. The generator's seat numbering (master spec §7.6.1) doesn't always pair seats as (2j-1, 2j). With 3 brackets, top 1, the semifinal is seats 2 and 3. So the site must never pair seats by arithmetic; it groups them by match.

    Every reader of STANDINGSCSV finds its columns by header name, so the two extra columns break nothing. These are the readers checked at the commits above:

    • the site's rowsToStandings;
    • sage-tools-api's SheetsCsvFetcher/GvizCsvFetcher, which read the whole tab;
    • src/attendance/domain/roster.mjs (headerIndex);
    • src/sync/domain/facilityCompletion.mjs.

    No sage-tools-api service change and no package.json bump.

    7.3.1 parseFrom(text)¶

    7.3.4 buildBracket(rows, model)¶

    rows are all of one category's standings rows (what categoryCardHTML receives). It returns:

    {
  linked: boolean,          // every playoff row has a non-empty `match`
  category: string,         // parseCode(firstPlayoffRow.teamCode, 'standard').category
  rounds: [                 // earliest → latest, BRONZE excluded, in sortStageKeys order
    { key: 'R16'|'QF'|'SF'|'FINAL'|…, label: STAGE_META[key].label, matches: [Node] }
  ],
  bronze: Node | null,
  eligible: boolean,        // rounds.length >= 2  (D5)
}

    A Node is { id, stageKey, games: [Game] }. It has more than one Game only for a series final (F (1), F (2), …). A Game is:

    {
  id,        // the `match` value, or a made-up id in the fallback: `${stageKey}-${i+1}` (or `${stageKey}-${i+1} (${g})`)
  m,         // model.matchByCode.get(seat code of either seat) — the scheduled Match, or null
  notNeeded, // !!m && model.unneededGames.has(m)
  seats: [Seat, Seat],
}

    A Seat is:

    {
  row,       // the standings row (may be undefined: a game with one row)
  code, rest,
  from,      // parseFrom(row.from), or null
  empty,     // !row || isEmptyStanding(row)
  result,    // 'win' | 'loss' | ''  (from m: played and unequal scores)
  score,     // m.t1Score / m.t2Score for this seat when m.played, else null
}

    Which rows count. Rows whose standingsStageKey(code, 'standard') !== 'RR', minus isByeStandingRow rows. If categoryBronzeIsByeDecided(model, category), drop the BRONZE rows: that's the same rule as stageTablesHTML.

    Linked grouping. Group rows by row.match in row order.

    • In each group, order the seats by the seat number in the code: the first integer after the stage keyword, /_(?:R32|R16|QF|SF|F|B)_(\d+)/.
    • A group with one row gets an undefined second seat. That happens with hand-edited data; the Seat then has empty: true.
    • Groups whose id matches /^(.+) \((\d+)\)$/ and share the first capture form one series Node, with games in game order. Every other group is a Node of one game, whose id is the group's match.
    • A node's stageKey is standingsStageKey of its first seat's code.

    Fallback grouping (not linked). Per stage, pairUpMatchups(stageRows), the existing function, which stays in views/standings.js.

    • It is not importable from domain/. So move its body into domain/bracket.js as pairPlayoffRows(rows), and keep pairUpMatchups in views/standings.js as a one-line wrapper calling it. The export stays, and its behaviour is identical.
    • Each pair is a Game. Series games are pairs whose codes carry matchInstanceOf. In the FINAL stage they form one Node, in instance order.

    Node order within a round.

    • Linked: by the number after the last - in the id (QF-2 → 2), then id text.
    • Fallback: in the order the pairs arrived.

    Score and result. For each game, m is the Match whose t1 or t2 equals a seat's code. A seat's score is m.t1Score when m.t1 === seat.code, else m.t2Score, and only when m.played. When played with unequal scores, the higher score's seat is 'win' and the other 'loss'.

    7.3.5 bracketShapeKey(bracket, rows)¶

    null when not linked. Otherwise:

    • groups = the number of distinct non-empty bracket values among the category's round robin rows (at least 1).
    • fresh = the number of seats, over all nodes and the bronze, whose from is null.

    7.3.6 seatText(seat, ctx)¶

    ctx = { playoffSeats, category, shapeKey, rrRows, linked }. It returns { kind, names, label, tag }, where kind is 'pair' | 'winner' | 'loser' | 'label' | 'qualifier' | 'tbd'. Apply the first case that fits:

    1. !seat.empty → kind 'pair', with:
    2. names: [player1, player2];
    3. tag: sourceTag(seat.row, rrRows) only when seat.from === null, else ''.
    4. seat.from → kind 'winner' or 'loser', label: 'Winner of ' + matchDisplayLabel(from.match) (or 'Loser of …').
    5. A label exists: playoffSeats[category]?.[seat.rest] ?? playoffSeats[shapeKey]?.[seat.rest] → kind 'label', label.
    6. linked → kind 'qualifier', label: 'Qualifier'.
    7. Otherwise → kind 'tbd', label: 'TBD'.

    sourceTag(row, rrRows). rrRows are the category's round robin rows that are not empty and not BYE.

    • Normalise a name: lower-case it, collapse runs of whitespace to one space, and trim.
    • A pair's key is its two normalised names, sorted, joined with |.
    • Find the round robin rows with the slot's key. If there is not exactly one, return ''.
    • Otherwise take its bracket b. Its rank is its 1-based position in rankByWinsThenQuotient of the round robin rows sharing b.
    • Return `Br ${b} · #${rank}`, or `#${rank}` when b is empty.

    7.3.7 layoutBracket(bracket, dims)¶

    Pure geometry. dims = { cardW, colGap, headH, seatH, rowGap, captionH, bronzeGap, seriesGap }. It returns:

    {
  width, height,
  captions: [{ text, x, y }],                 // one per round, at y = 0, plus 'Bronze Battle' above the bronze
  nodes: [{ node, x, y, h }],                 // h = games.length * cardH + (games.length - 1) * seriesGap
  lines: [{ d }],                             // SVG path data, linked only
}

    Here cardH = headH + 2 * seatH. Round i's x = i * (cardW + colGap), and width = rounds.length * cardW + (rounds.length - 1) * colGap.

    Linked:

    1. feeders(N): for each seat index k (0 or 1) of the node's first game, whose from.kind === 'W' and whose from.match is the id of a game of some node F → { k, F }, in k order.
    2. cursor = captionH, y unset everywhere. place(N):
    3. Return if N is placed; mark it placed; place(F) for each feeder, in order.
    4. No feeders: N.y = cursor.
    5. One {k, F}: N.y = F.y + F.h/2 - (headH + k*seatH + seatH/2), so F's middle lines up with the seat it feeds.
    6. Two: N.y = mean(F.y + F.h/2) - N.h/2.
    7. Then cursor = max(cursor, N.y + N.h + rowGap).
    8. Call place on the last round's nodes in order. Then, for every round from first to last, on its unplaced nodes in order: matches the Final can't reach.
    9. Overlaps: in each round, sort by y; any node closer than prev.y + prev.h + rowGap moves down to that.
    10. Normalise: shift every y by captionH - min(y) when that is positive.
    11. Bronze: at the last round's x, y = max(bottom of every node) + bronzeGap. Its caption Bronze Battle sits at y - captionH + 4.
    12. Lines: for each node N and feeder {k, F}: x1 = F.x + cardW, y1 = F.y + F.h/2, x2 = N.x, y2 = N.y + headH + k*seatH + seatH/2, xm = x1 + colGap/2, and d = M x1 y1 H xm V y2 H x2. Round to whole pixels.
    13. height = max(bottom of every node, the bronze included).

    Fallback: each round's nodes are stacked from captionH with rowGap. Each column is then centred vertically on the tallest column. No lines. The bronze is placed as in linked step 6.

    14. Divergences¶

    The build follows the spec; these are the places it differs from the text, or fills in what it leaves open.

    • The Full tree layer's CSS selector is div.bk-full (§7.7). §7.4 gives the span that holds a pair's full names the class bk-full, and §7.7 gives the layer the same class, so a plain .bk-full{position:fixed…} would make every name span a fixed layer. The markup is as written; only the layer's rules are scoped to the div.
    • The narrow-screen strip is the chart, not a strip of rounds (§2.3, §7.4; owner's request, 22 October). roundStripHTML returns the chips and bracketChartHTML's chart in .bk-track, with an <i class="bk-snap"> at each round's left edge for the swipe to settle on. A chip carries data-bk-x (its round's left edge in px) and the strip data-bk-start-x; the last chip is lit once the window is scrolled to its end. The .bk-round columns and .bk-round-caption are gone. Full tree is also under the whole chart (fullTreeButtonHTML), so a tablet that fits the chart has it too.
    • On desktop the column keeps its width; it does not widen to the chart (§2.1, D7, §7.6; owner's request, 22 October). Widening made the board jump on every List / Bracket switch, and shrank a side-by-side category's 740px column to its chart. createStandings passes fixedColumn: true on the desktop layout, and categoryCardHTML then gives the chart the column's own room, less the card's padding and COLUMN_CHROME (its border and 5px scrollbar): two rounds at a time for side-by-side brackets, else one (stageTablesHTML's roundsInView), whether or not the whole chart would fit; a chart with no more rounds than that is drawn whole, its cards stretched, with no chips. Without fixedColumn, standings-col--bracket is added only for a chart wider than the column's own width (740px when side by side). WIDE_COLUMN_WIDTH, CARD_BORDER and COLUMN_CHROME are exported.
    • The window holds whole rounds (§2.3, §7.4; owner's request, 22 October). roundStripHTML takes the window's width and perView, stretches every card to fitCardWidth(width, perView) (never under 172px), caps .bk-track at exactly those rounds, snaps mandatory (bk-rounds--fit) and carries data-bk-card-w and data-bk-per-view; createStandings lights the chip of every round wholly in view. A phone's room is the card body less its padding and border, one round at a time.
    • The List / Bracket switch heads the playoffs, not the title (§7.6; owner's request, 22 October). A standard category's card titles its sections: Round Robin and Playoffs are .standings-section-titles (Archivo Black with a rule to the card's edge; stageTablesHTML's sectionTitles), the stage captions and bracket labels under them their subtitles. The switch sits at the end of the Playoffs title (.standings-section-title.playoffs-head, viewSwitch) in both views; a category with one playoff round has the title without it. A dual meet's stages keep the plain stage-caption.
    • The workbook labels its own seats (§6, D2; owner's request, 22 October). Standard Tournament Generator 1.4.0 adds a fourth link-table column, Variables!AG seat, and STANDINGSCSV!J seat looks it up; the generator fills it for the shapes the organisers seat by rule (two brackets; three and four brackets, top 2) and Add bracket links adds it to older workbooks, keeping a label already typed there. rowsToStandings reads seat, and seatText shows it on an empty seat no match fills before display.playoffSeats, which stays as the fallback for a workbook without the column.     • Full tree's fit can enlarge the chart (§7.7; owner's request, 22 October).
