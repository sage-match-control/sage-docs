    Spec — Mission Control layout, shared sign-in, and attendance marks¶

    Status: in progress. Written 2026-11-21 against the site's main that day (tools/control-center.html, lib/v1/, _tests/) and sage-tools-api 3.8.0, and agreed with the owner from two mockups. Three phases, all three to merge before the UPAP 3rd Annual (22 November 2026) by the owner's decision (§1 D11). Built on 2026-11-21, all three phases, on the mission-control-layout branch of the site repo (one commit per phase, each passing npm run verify), of sage-docs and of the workspace repo; not pushed or merged. The owner's checks (§15.2) and the merge are left. See the Divergences at the end for where the build departs from the text below. Every decision is settled (§1).

    • Phase 1: Mission Control rearranged into cards that use a desktop screen's width, with a link to the Scoresheet Generator; and the operator's sign-in shared between the browser's open Control Center tabs.
    • Phase 2: in Control Center, a mark on every player who is not checked in yet, in Match Finder, Live Matches and Standings, a count per match, and a count per venue.
    • Phase 3: the same marks on the schedule board, in a staff view that only a browser with a signed-in Control Center tab can see.

    0. Read this first¶

    This spec is written for an implementer with no other context. Build the phases in order, each one finished and checked (§14) before the next. Within a phase, do the sections in the order written. Finish as §15 says.

    0.1 The system in one paragraph¶

    S.A.G.E. runs pickleball tournaments. Each tournament day has one Google Sheet per venue ("facility workbook"). A Cloud Run service, sage-tools-api, publishes each day's matches and standings as a JSON snapshot that every page reads. The site (sage-match-control.github.io) is static HTML and native ES modules: no build step, no framework. Its shared code is the engine, lib/v1/, in layers: platform.js, domain/ (pure rules), data/ (fetching, sockets, storage), views/ (HTML builders) and apps/ (whole pages). Control Center (tools/control-center.html, one file, about 4,850 lines) is the operators' console; its first tab, Mission Control, is where an operator signs in. Each event has a public Tournament Hub (events/<key>/index.html) and a schedule board (events/<key>/schedule.html, the venue wall display, lib/v1/apps/schedule-board.js), both thin shells over the engine. Events with attendance have an ATTENDANCE tab in each workbook: one row per person, with a present tick box; staff tick people in from Control Center's Attendance tab or a desk page. The API serves that list to signed-in operators (GET /v3/days/{day}/facilities/{facility}/people), and a Cloudflare Worker sends a data-free "nudge" over a WebSocket when someone is ticked, so open pages re-read it.

    0.3 Hard rules¶

    1. Branches, never pushes. Work on a branch named mission-control-layout in sage-match-control.github.io and in sage-docs, and commit there, at least one commit per phase, in phase order. Each phase's last commit must pass npm run verify on its own, so the owner can merge phase by phase. Never push or merge. The owner does that (§15.2).
    2. lib/v1 changes are compatible only (_templates/CLAUDE.md §8). You may add a file, an option or a CSS rule. You may never remove or rename an export, a CSS class a page uses, or a theme property. With the new options absent, every existing function returns byte-for-byte what it returns today.
    3. No new export of an existing engine file is imported anywhere. A browser may serve an engine file from its cache for up to 10 minutes after a push, so a module that imports a name its cached neighbour doesn't have yet breaks the whole page. Every new function another file imports goes in a new file (§7, §8, §6). New options on existing functions are fine: an old cached copy ignores an option it doesn't know.
    4. Nothing in views/ or domain/ names an operator feature (the guards.test.mjs rule): the view hooks are neutral (markPlayer, matchNote), and the attendance words live in Control Center, data/ and apps/.
    5. The public pages show nothing new. The Hub never passes the new options. The board shows marks only in its staff view with a sign-in (§11). Printing never shows them.
    6. Do not change: sage-tools-api, event-data, any Apps Script, the live Worker, the snapshot format, events.json's shape, the Attendance tab's own list, the desk and scorer pages, team events' views (views/teams.js), any event shell (events/*/index.html, events/*/schedule.html), or anything under events/archives/.
    7. Never call the production API and never sign in for real. Check with the fixtures and a fake token (§14).
    8. Never weaken or delete a test to make one pass. The test changes are the ones §12 lists.
    9. Write docs in the present tense (workspace CLAUDE.md).

    // The operator's sign-in, shared between this browser's open pages of the site
// (sage-docs/docs/specs/.../mission-control-layout-spec.md §6). A BroadcastChannel
// reaches only same-origin pages in this browser profile: never another device,
// another browser or a private window. It carries { token, expiresAt } and nothing
// else; nothing here touches storage or a URL.
//
// Messages: { type: 'ask' }, { type: 'session', token, expiresAt }, { type: 'signed-out' }.

export const OPERATOR_SESSION_CHANNEL = 'sage.operator-session';

const valid = s => !!s && typeof s.token === 'string' && s.token !== ''
  && typeof s.expiresAt === 'number' && s.expiresAt > Date.now();

/**
 * @param {{ getSession?: () => ({ token: string, expiresAt: number } | null),
 *           onSession: (s: { token: string, expiresAt: number }) => void,
 *           onSignedOut: () => void,
 *           answer?: boolean }} options
 *   getSession   this page's own unexpired sign-in, or null. Read only when answer is true
 *   onSession    another page signed in, or answered an ask, with an unexpired sign-in
 *   onSignedOut  another page signed out
 *   answer       true (Control Center): answer other pages' asks. false (the board): never answer
 * @returns {{ ask(): void, announce(s): void, signedOut(): void, close(): void }}
 *   Without BroadcastChannel every method does nothing.
 */
export function createOperatorSession({ getSession = () => null, onSession, onSignedOut, answer = true }){
  if(typeof BroadcastChannel !== 'function') return { ask(){}, announce(){}, signedOut(){}, close(){} };
  const channel = new BroadcastChannel(OPERATOR_SESSION_CHANNEL);
  channel.onmessage = e => {
    const msg = e.data || {};
    if(msg.type === 'ask'){
      if(!answer) return;
      const s = getSession();
      if(valid(s)) channel.postMessage({ type: 'session', token: s.token, expiresAt: s.expiresAt });
    }else if(msg.type === 'session'){
      if(valid(msg)) onSession({ token: msg.token, expiresAt: msg.expiresAt });
    }else if(msg.type === 'signed-out'){
      onSignedOut();
    }
  };
  return {
    ask(){ channel.postMessage({ type: 'ask' }); },
    announce(s){ if(valid(s)) channel.postMessage({ type: 'session', token: s.token, expiresAt: s.expiresAt }); },
    signedOut(){ channel.postMessage({ type: 'signed-out' }); },
    close(){ channel.close(); },
  };
}

    A BroadcastChannel never delivers a message to the object that sent it, so a page never hears its own ask.

/** A person's key: their name with accents, case and spacing ignored. The server's personKey, exactly. */
export function attendanceKey(name){
  return String(name ?? '')
    .normalize('NFD').replace(/[\u0300-\u036f]/g, '')
    .replace(/\s+/g, ' ')
    .trim()
    .toLowerCase();
}

/**
 * One lookup for the whole day, from every facility's people (Person[] arrays).
 * key -> { present, withdrawn }: present if present at any facility; withdrawn only if withdrawn at every one it is on.
 * @param {object[][]} lists
 * @returns {Map<string, { present: boolean, withdrawn: boolean }>}
 */
export function attendanceIndex(lists){
  const index = new Map();
  for(const people of lists || []){
    for(const p of people || []){
      if(!p || !p.key) continue;
      const was = index.get(p.key);
      index.set(p.key, was
        ? { present: was.present || !!p.present, withdrawn: was.withdrawn && !!p.withdrawn }
        : { present: !!p.present, withdrawn: !!p.withdrawn });
    }
  }
  return index;
}

/** True when the name is on the roster, not withdrawn and not present. A name not on it (TBD, BYE) is false. */

  return !!e && !e.withdrawn && !e.present;
}

export function matchNotInCount(m, index){

    Divergences¶

    Where the built code departs from the text above, and what the build could not check. The intent of each section stands.

    1. §10 item 3, attMarksChanged() redraws Match Finder whichever tab is showing. The text redraws it only while Match Finder is the tab on screen. A day loads while Mission Control is showing, and Match Finder's list is drawn once then and lives on while its tab is hidden, so a list drawn before the first people read arrived stayed unmarked until something else redrew it (the harness's finder view showed no marks). Live Matches and Standings are drawn each time their tab opens, so they are redrawn only when on screen, as written.
    2. §9.3 item 4, stageTablesHTML has two pairCell calls, not three. The Round Robin table has one in each of its two layouts (§0.4 says "both table layouts"); both pass { markPlayer }.
    3. §11.2 item 4, a team event's staff view marks nothing. The text leaves teamSideNamesHTML unchanged (D18) but would still count and tag a team card. The N not in tag is left off team cards too, so a team card is never half marked.
    4. §11.2 items 6 to 8, one staffSession function. The expiry timer is set in a staffSession(s) that both the channel's onSession and the fixture call, clears a previous timer and is cleared by staffStop; in fixture mode the board takes the fixture sign-in and does not also ask the channel.
    5. §12.2 item 4, the board's staff and staff-print cases pass the operatorSession and cloudRun through a fourth element of the view tuple. staff-print and staff-no-session match the baseline exactly, as required.
    6. §14 checks not done as written.
    7. §14.2 item 4 (sign out removes every mark) was not shown in the browser: with ?fixture= Control Center counts as signed in whatever the token (attConsoleSignedIn() is !!FIXTURE || …), so the fixture keeps its marks. attStatusRestart() runs from renderAuthStatus() whenever the signed-in state changes, which is what removes them.
    8. §14.2 item 2 (marks on Live Matches rows): the fixture's pre state has no match on a court. The rows and chips were checked in the harness's live views (mid), and the venue line in the fixture.
    9. §14.1 item 6: the Scoresheet Generator reads the real events.json, which has no fixture event's day, so the ?day= link was checked with a real day key (piggleball-day1) and the tile's href against the fixture's.
    10. §14.3 item 2 (a board in a new tab against the real API) was not run: it would call the production API, which this build was told not to. A board with no sign-in staying the public board is the harness's staff-no-session case. The sign-out and sign-in messages, the expiry timer path and the filters keeping ?staff=1 were checked on a throw-away board page for the fixture event (untracked, *beta*).
    11. §4 and §11.3 values are as written. On a phone the board's N not in tag wraps to a line of its own in the card's top line (that line already wraps on a narrow screen), which adds a line of height to an unplayed card there. The harness's screenshots show it; nothing was changed.
